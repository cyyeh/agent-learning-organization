AI / Agent Engineering · Learning Organization

把「不知道」快速變成
團隊共同能力

對 3–4 位工程師的小團隊，不必做大型知識管理。 重點是建立一個短迴路：從真實工作發現問題，用小實驗驗證，再把結果沉澱成可重用的工程資產。

學習型組織 ≠ 大家一直上課；而是團隊能持續把未知轉化成經過驗證的共同知識。

什麼是「學習型組織」？

核心定義

學習型組織不是「大家常上課」或「公司有很多分享會」，而是：

團隊能持續發現問題、產生新知、分享知識，並真的改變後續的決策與工作方式。

判斷標準

  • 能暴露未知：知道自己還不知道什麼
  • 能快速驗證：用實驗與證據取代直覺爭論
  • 能跨人傳遞：知識不只停留在個人
  • 能形成改變：學到的東西會進入流程、程式碼與決策

這個 Agent Engineering Lab 與學習型組織的關係

1. 真實工作產生問題

不從課本選題，而是從產品、agent failure、效能瓶頸與開發流程中找到真正的未知。

2. Lab 把問題變成共同學習

透過 hypothesis、baseline、experiment、trace 與討論，把個人經驗轉成團隊可驗證的知識。

3. 學習回到 Production

將結論沉澱成 eval、test、pattern、tool、ADR 或 guardrail，真正改變下一次工程實作。

Agent Engineering Lab 是「學習型組織」的實作載體：讓學習不只發生在人的腦中，而是進入團隊流程與工程系統。

不要建立「主題池」

少一點：MCP、Memory、Multi-Agent、RAG……

改成建立「問題池」

  • Subagent 什麼情況真的比 single-agent 好？
  • Context 多到什麼程度開始降低表現？
  • 哪些 failure 是 model，而不是 tool / retrieval / harness？
  • 什麼任務根本不值得使用 agent？

把「我不知道」變成資產

鼓勵工程師把 uncertainty 公開化，不要求立即有答案。

「這兩週你遇到最值得團隊搞清楚的一個『我不知道』是什麼？」

最小制度：小團隊就做這 6 件事

機制節奏目的
#agent-radar隨時蒐集值得驗證的新資訊與問題
Question Backlog持續管理 Unknown → Hypothesis → Experiment → Decision
Agent Engineering Lab每兩週 75 分鐘一次只回答一個真實工程問題
Failure → Eval工作中持續把 bug / failure 轉成 regression case
Owner + Shadow每季輪替避免知識只存在單一工程師身上
Learning Review每季一次檢查哪些新知真的改變了 production

Agent Lab 每次只做一件事：回答一個問題

會議前

  • 定義問題與 hypothesis
  • 準備 baseline
  • 帶一個成功 trace + 一個失敗 trace

會議中

  • 拆解 failure
  • 做一個小型 ablation
  • 形成 Adopt / Experiment / Reject / Revisit 決策

知識要一路壓縮成「可執行資產」

資訊

文章、paper、GitHub、AI summary

團隊知識

Insight、Pattern、Decision、Failure Taxonomy

Executable Knowledge

Eval、Test、Reusable Tool、CI Guardrail、Reference Implementation

最理想的分享產物不是 PPT，而是下一位工程師能直接重用或系統能自動執行的東西。

Leader 的角色

  • 不是成為「最懂 AI 的人」
  • 提出好問題
  • 要求證據與 baseline
  • 鼓勵反例與失敗案例
  • 確保學習被沉澱與擴散

季度 Learning Review

  • 三個月前不知道、現在知道什麼？
  • 哪些 assumption 被推翻？
  • 哪些實驗真的改變 production？
  • 有哪些知識仍只存在個人腦中？
最終成功指標
當團隊遇到一個沒有人知道答案的新 AI / Agent 工程問題時，
是否能自己快速把它變成一個可靠、可重現、可共享的答案？
